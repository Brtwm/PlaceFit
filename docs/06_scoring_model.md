# Scoring Model — PlaceFit MVP

## Принцип

Rule-based модель. Детерминированная: один и тот же ввод всегда даёт один и тот же score.

## Total score

```
total_score = demand + competition + rent + premises + accessibility
max = 35 + 25 + 20 + 10 + 10 = 100
```

---

## 1. Demand score (max 35)

| Условие | Баллы |
|---------|-------|
| `high_density_area = true` | +15 |
| `new_residential_area = true` | +15 |
| Базовый спрос (всегда) | +5 |

**Ограничение MVP**: оба признака — ручной ввод пользователя. Сначала эти
признаки нужно проверить в V1.1 manual validation; автоматизация возможна только
после подтверждения качества источников данных.

---

## 2. Competition score (max 25)

### По радиусу 300 м

| Конкурентов | Баллы |
|-------------|-------|
| 0 | +10 |
| 1 | +7 |
| 2 | +4 |
| 3+ | +1 |

### По радиусу 700 м

| Конкурентов | Баллы |
|-------------|-------|
| 0–2 | +10 |
| 3–4 | +7 |
| 5–6 | +4 |
| 7+ | +1 |

### Бонус за отсутствие ближайшего

| Ближайший конкурент | Баллы |
|---------------------|-------|
| > 500 м | +5 |
| 300–500 м | +3 |
| 150–300 м | +1 |
| < 150 м | +0 |

**Примечание**: наличие 1–3 конкурентов в 700 м может подтверждать спрос. Полное отсутствие — не всегда лучше (может означать отсутствие спроса).

---

## 3. Rent score (max 20)

| Аренда (₽/мес) | Баллы |
|-----------------|-------|
| ≤ 60 000 | 20 |
| 60 001 – 90 000 | 15 |
| 90 001 – 130 000 | 8 |
| > 130 000 | 2 |

Пороги хранятся в конфигурации (scoring_rules или scoring_versions JSONB).

---

## 4. Premises score (max 10)

| Фактор | Баллы |
|--------|-------|
| `first_floor = true` | +3 |
| `separate_entrance = true` | +2 |
| Площадь 20–60 м² | +2 |
| `storage_area = true` | +2 |
| `signage_possible = true` | +1 |

Площадь < 20 м² или > 80 м²: +0 за площадь.
Площадь 15–20 м² или 60–80 м²: +1.

---

## 5. Accessibility score (max 10)

| Фактор | Баллы |
|--------|-------|
| `parking = true` | +3 |
| `bus_stop_nearby = true` | +3 |
| `good_visibility = true` | +2 |
| `separate_entrance = true` (удобство входа) | +2 |

**Примечание**: `separate_entrance` учитывается и в premises, и в accessibility — это намеренно, т.к. он влияет на оба аспекта.

---

## Decision

| Условие | Решение |
|---------|---------|
| score ≥ 75 AND net_profit > 0 (или доход не указан) | `можно рассматривать` |
| score 60–74 | `проверить дополнительно` |
| score < 60 | `скорее не открывать` |
| score ≥ 75 AND net_profit ≤ 0 | `проверить дополнительно` |
| rent > 130 000 | доп. предупреждение |

## Confidence score (max 100)

Отдельный от total_score. Показывает надёжность оценки.

### Компоненты

| Компонент | Max | Логика |
|-----------|-----|--------|
| source_completeness | 25 | 2+ источника POI: 25, 1 источник: 15, 0: 0 |
| freshness | 20 | Данные < 7 дней: 20, < 30 дней: 15, > 30 дней: 5 |
| manual_input_reliability | 20 | Автоматически подтверждены или проверены ключевые поля: 20, ключевые поля заполнены вручную: 10, частично: 5 |
| competitor_data_confidence | 20 | ≥ 3 POI найдено: 20, 1–2: 10, 0 (подозрительно): 5 |
| finance_data_confidence | 15 | expected_income указан: 15, не указан: 5 |

### Пример

```
Данные из 2GIS + Yandex (2 источника): 25/25
Данные свежие (< 7 дней):             20/20
Ключевые поля заполнены вручную:      10/20
5 конкурентов найдено:                20/20
expected_income указан:               15/15
                                      -----
confidence_score:                     90/100
```

## Scoring versioning

- Каждый набор правил хранится в `scoring_versions` с JSONB.
- Каждый анализ привязан к `scoring_version_id`.
- При изменении весов — новая версия, старые не удаляются.
- MVP стартует с `v1.0`.
- UI/admin для управления версиями, сравнение результатов между версиями и история изменений — V1.5 scoring governance.

---

## Ограничения

1. Demand score сильно зависит от ручного ввода.
2. Competition score не учитывает «силу» конкурента (рейтинг, объём заказов). Это можно рассматривать только после V1.1 validation; не добавлять как скрытую ML/black-box логику.
3. Нет данных о пешеходном трафике — ручной чек-лист.
4. Пороги аренды — для Краснодара. Для других городов нужны другие пороги.
5. Владелец завершил 45 ручных проверок и сообщил `PASS` по всем кейсам;
   детальные карточки кейсов в репозиторий не добавлены.
